# Coworking Space Reservation System (REST API)

Бэкенд-сервис для бронирования рабочих мест и переговорных комнат в коворкингах. 
Разработан по принципам Clean Architecture с фокусом на консистентность данных при конкурентных запросах.

## Архитектурные особенности

- **Слоистая архитектура (Clean Architecture):** Четкое разделение ответственности на Handler (транспорт), Service (бизнес-логика), Repository (доступ к данным). Внедрение зависимостей через конструкторы (Dependency Injection).
- **Конкурентность и целостность данных:** Предотвращение овербукинга (Race Condition) реализовано на уровне СУБД с помощью атомарного запроса `INSERT ... SELECT WHERE NOT EXISTS` с проверкой пересечения временных интервалов.
- **Безопасность:** Stateless-аутентификация на базе JWT (HMAC-SHA256). Ролевая модель доступа (RBAC) через цепочку middleware (`admin` / `client`).
- **Контейнеризация:** Multi-stage сборка Dockerfile (размер финального runtime-образа на базе Alpine ~20 MB).

## Стек технологий

- **Язык:** Go 1.27+
- **База данных:** PostgreSQL 16
- **Драйвер БД:** `pgx/v5` (пул соединений `pgxpool`)
- **Миграции:** `golang-migrate`
- **Аутентификация:** `golang-jwt/jwt/v5`,`bcrypt`
- **Инфраструктура:** Docker, Docker Compose, Makefile
- **Архитектура:** Clean Architecture / Feature-Driven Design

## Схема базы данных

- **`users`** — пользователи и роли (`admin`, `client`)
- **`spaces`** — локации / здания коворкингов
- **`rooms`** — комнаты внутри локаций (вместимость, часовая ставка, связь с space_id)
- **`bookings`** — бронирования с контролем пересечений интервалов и статусами (`active`, `cancelled`)

## Быстрый старт

### Требования
- Docker и Docker Compose
- Утилита `make`

### Запуск проекта

1. Клонировать репозиторий:
   ```bash
   git clone https://github.com/artemida000/go-coworking-booking.git
   ```

2. Создать файл окружения из шаблона:
   ```bash
   cp .env.example .env
   ```

3. Поднять контейнеры с базой данных и приложением:
    ```bash
    make docker-up
    ```
4. Применить миграции базы данных:
    ```bash
    make migrate-up
    ```
Сервис будет доступен по адресу: http://localhost:8080

### Запуск тестов
    make test

## API Эндпоинты

| Метод | Эндпоинт | Доступ | Описание |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/register` | Public | Регистрация пользователя |
| `POST `| `/api/login` | Public | Аутентификация, выдача JWT |
| `GET` | `/api/spaces` | User | Список всех коворкингов |
| `POST` | `/api/spaces` | Admin | Создание коворкинга |
| `GET` | `/api/spaces/{id}/rooms` | User | Список комнат в коворкинге |
| `POST` | `/api/rooms` | Admin | Создание комнаты |
| `POST` | `/api/bookings` | User | Создание бронирования |
| `GET` | `/api/bookings/my` | User | Список бронирований текущего пользователя |
| `DELETE` | `/api/bookings/{id}` | User | Отмена бронирования (soft delete) |

## Перспективы масштабирования (Roadmap)

В случае роста нагрузки архитектура позволяет:
1. Выделить сервис уведомлений в отдельный микросервис с межсервисным взаимодействием по gRPC.

2. Внедрить брокер сообщений (Apache Kafka / RabbitMQ) для асинхронной обработки событий создания и отмены бронирований.

3. Интегрировать Redis для кэширования каталога локаций и комнат.
